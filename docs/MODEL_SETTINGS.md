# 管理端模型接入

管理员从左下角账户入口进入独立管理后台，再打开“模型接入”。此页面配置对话生成模型，使用 OpenAI 兼容 `/chat/completions` 格式；基础地址填写到 `/v1` 或服务商要求的前缀，不包含 `/chat/completions`。现有向量模型配置保持独立。

可以调整模型 ID、调用地址以及替换密钥。页面只接收掩码密钥：长度足够时显示前 6 位和后 4 位，短密钥全部掩盖。掩码不可选中或复制，没有完整密钥查看、复制或导出接口。替换框为空的密码输入框，不会预填旧密钥，保存或取消后清空。只修改模型时保留原密钥；更换调用地址的域名或协议时，需要填写对应新密钥，避免把旧密钥发往新服务。

保存无需重启。私有 AI 服务原子发布新的不可变运行配置，新请求使用新配置，已开始的生成继续使用其原快照。普通任务、对话流和记忆摘要共用此规则。revision 检查防止管理员间覆盖更新，写盘失败保留原运行配置。

保存的数据持久化到 AI 服务的私有配置文件，权限 0600，使用临时文件和原子替换。默认路径是 KNOWLEDGE_DIR 的父目录下 `model-settings.json`，本地脚本对应 `.runtime/local/model-settings.json`（已忽略提交）；可通过 MODEL_SETTINGS_PATH 指定。启动后优先加载保存配置，没有保存配置时读取环境变量。此文件包含服务端密钥，应随私有服务数据保护，不能放入静态目录或仓库。

`GET /api/admin/model-settings` 返回 model、baseUrl、maskedKey、hasKey、revision、updatedAt、format；不返回原密钥。`PUT` 接收 model、baseUrl、revision，apiKey 可选。普通用户与未登录请求均被拒绝。Java 通过现有内部认证代理到 AI 服务，不把内部凭据传给前端。

验证覆盖：热切换后实际请求的模型/地址/Authorization、新旧运行快照隔离、重启读取持久配置、写盘失败回滚、版本冲突、地址校验、密钥保留与更换、掩码不复制、普通用户不可访问。实际本机已在保存前后比对 AI 和 Java 进程号，确认未重启；当前保留原 qiniu/conatus-free 模型。
