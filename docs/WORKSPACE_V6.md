# 新闻驱动的连续创作

用户给出新闻领域后，Agent 可以调用 `search_news` 获取公开报道，再用 `read_news` 查看已获取的来源快照。检索结果会保留在同一对话内，后续讨论和作品生成可以继续引用。只有用户明确要求生成整套作品时才写入作品。

新闻证据分别记录原始发布时间、抓取时间、来源和正文或摘要状态。对话回复必须说明原始发布时间；无法确认时明确标注，不能用抓取时间代替。当前接入公开新闻索引、媒体目录和允许抓取的网页，不提供平台真实热榜排名，也不代表事实已经独立核实。遵守 robots 限制，限制请求频率、大小、跳转与可访问域名。

右侧工作区合并执行记录、原文链接和作品入口，不再分为三个页签，不显示“已就绪”。新闻卡片直接打开媒体原文，不显示全文副本。左侧工具栏移除重复的历史按钮，聊天页头继续控制独立的历史栏。

“我的作品”按行展示。点击作品进入 `/works/:id` 阅读；点击“修改”进入 `?edit=1`，在文稿中点击段落即可编辑，也可在右侧沿用原对话向 Agent 提出修改要求。脚本、分镜、拍摄、配音、剪辑和发布使用滑动切换。手动修改保存为新版本，发送 Agent 修改前先保存未提交的文稿，避免覆盖。保留版本恢复和导出。

验证：前端构建通过，前端 61 项测试通过，Python 96 项测试通过，Java 集成测试包含新闻来源持久化和跨用户隔离。实际已抓取央视新闻正文与原始发布时间，并在浏览器验证作品列表、只读详情和段落编辑。真实模型已能基于保留的新闻证据回复原始发布时间并比较选题，但选题卡片语义校验和后续完整作品请求遇到供应商 HTTP 429（返回代码 `free_campaign_global_limit`，免费模型全局限流），完整新闻到新作品链路仍需在限流解除后完成验收；未切换演示数据或其他模型。

## 首轮选项与持续运行

首轮明确提出视频创作且已提供主题或检索到对应新闻时，直接输出结构化 A/B/C 选择卡片，D 为自定义入口。正文总结不代替卡片。普通问候、无方向的需求、纯新闻查询和明确请求整套作品不强制追加选题。卡片由实际结构化生成工具产生并持久化，失败按模型重试策略处理，不用固定演示选题补齐。

消息区横向留白缩小。重新生成图标和历史列表对应运行会话使用独立旋转动画；列表每三秒刷新，当前会话状态即时同步。浏览器断开只关闭事件订阅，不取消后台任务。重新进入从持久化状态和事件恢复，仍受原执行时限、服务可用性和手动停止控制。

## 方案卡片与已有作品附件

已提交的 `artifact.updated` 事件在对应助手回复下方显示作品方案卡片，点击进入只读详情，修改仍由详情页的“修改”按钮进入。卡片只对应实际保存成功的作品，不依据模型声称完成的文字伪造。

输入框附件菜单提供“上传文档”和“已有作品”。选择已有作品时，使用当前账户受权限保护的导出接口生成 Markdown 原稿，再通过同一文档上传与读取链路附到当前消息；待发送时可移除。原作品保持其版本，用户可在新会话明确要求基于附件生成修改副本，或在原作品会话继续改稿。不会跨对话静默覆盖原件。直接要求最终方案可绕过选题讨论，附件阅读总结仍不等于整套生成授权。
