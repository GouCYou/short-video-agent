# 对话式短视频创作工作台

## 交互与交付

首页采用导航栏、会话历史、对话区和执行侧栏四区布局，沿用暖白、鼠尾草绿和珊瑚橙配色。小屏通过抽屉展开历史和侧栏。用户直接发送消息开始讨论，无需先填写创作表单。

Agent 可以给选题、表达方向、观众、风格和制作方式提供 A/B/C 三张卡片。D 打开自定义输入，用户也可以继续自然语言讨论。已选卡片保留选择结果；新一组同类建议会使旧的未选卡片失效。后端按持久化的选项标识校验选择，拒绝伪造、重复与过期提交。

讨论和确认卡片不会自动生成整套作品。明确要求交付时，制作包包含定位、受众分析、标题、开场、分镜脚本、结尾、发布文案、拍摄计划、配音方案及剪辑步骤。分镜记录稳定 UUID、时长、画面、口播、字幕、景别、运镜、动作、配音要求、剪辑和素材。

作品支持对话修改、手动保存、版本对比与恢复、定稿、Markdown 或文本导出。此版本交付文字制作方案，不包含视频渲染、配音音频合成或平台发布。

## 动态工具

Python 对话 Agent 根据最新会话、需求快照及现有作品动态选择工具：

| 工具 | 功能 |
| --- | --- |
| update_brief | 更新用户已说明或确认的创作要求 |
| propose_options | 提供选题、方向、受众、风格或制作方式卡片 |
| search_knowledge | 检索知识库中的实际资料片段 |
| create_production | 生成完整文字制作包 |
| revise_production | 修改指定作品区块 |
| check_production | 检查结构、分段时长、口播字数与引用标识 |

工具循环最多 8 步、16 次工具调用、300 秒。优先使用供应商原生 tools；仅在明确不支持工具参数时使用结构化动作循环。网络失败、配置缺失与鉴权错误不会被替换为演示结果。显式 demo 模式使用确定性内容，并显示演示标记。

资料检索依赖独立的 Embedding 配置。配置缺失或检索为空不会编造资料；仍可继续创意工作。检查器只报告机械估计和引用标识一致性，不将其表述为事实核验。

## 实时执行与持久化

Java 业务服务负责权限、会话、消息、运行队列、事件、制作包和版本；Python 通过 NDJSON 输出真实执行事件。事件先保存 MySQL，再通过带 Bearer 鉴权的 SSE 推送。客户端按事件序号去重与续接，断线时通过详情接口兜底刷新。执行侧栏展示实际工具、状态、结果与耗时，不展示内部推理。

同一会话最多一个运行。消息提交支持幂等键，运行有独立租约，取消后拒绝迟到写入。制作包在收到有效最终结果后原子提交，失败或取消不会覆盖已有作品。排队运行可在重启后继续处理；租约到期的运行标记中断，避免静默重复模型调用。

分镜和作品版本保留稳定标识。局部改写只复制允许修改的字段，其他内容保留原值；手动保存校验 baseVersion，拒绝覆盖较新的稿件。恢复和定稿均追加版本，历史记录可追溯。

原有任务与管理员功能保留独立入口，已有数据不要求迁移至会话。

## 验证

`scripts/conversation_smoke.py` 验证会话隔离、选题与方向/观众卡片、D 自定义、重复提交、伪造选择拒绝、讨论边界、完整制作包、事件序号、SSE、手动编辑冲突、局部修改、版本恢复与导出。演示链路通过只能证明业务行为；真实模型的工具选择、文案质量、时延与资料质量需要独立验证。

接口见 `CONVERSATION_API.md`，运行记录见 `TESTING.md`。
